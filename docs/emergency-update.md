# Аварійне оновлення прошивки через REST API (Emergency Update)

Якщо на вашому пристрої встановлено прошивку на старій версії [ESPHome](https://esphome.io/) і через це внутрішній графічний WEB-інтерфейс (сторінка пристрою в локальній мережі) не завантажується або працює некоректно, ви можете ініціювати примусове оновлення «по повітрю» за допомогою прямих HTTP-запитів до ядра системи.

!!! info "Принцип роботи"
    Цей метод використовує вбудований [REST API](https://esphome.io/web-api/#api-rest) [ESPHome](https://esphome.io/), який працює у фоновому режимі незалежно від стану відображення графічного інтерфейсу дашборду.

## Крок 1. Перевірка статусу компонента оновлень

Перед початком варто переконатися, що пристрій підключений до вашої Wi-Fi мережі та бачить сервер із файлами оновлень. Для цього виконайте перевірку статусу.

=== "через Браузер"

    Відкрийте нову вкладку у вашому браузері та введіть у адресний рядок:

    ``` http
    http://<IP_ПРИСТРОЮ>/update/Firmware Update
    ```

=== "через Термінал (cURL)"

    ``` bash
    curl -X GET "http://<IP_ПРИСТРОЮ>/update/Firmware Update"
    ```

!!! abstract annotate "Очікувана відповідь від пристрою (JSON):"
    ``` json
    {
      "id": "update/Firmware Update",
      "state": "UPDATE_AVAILABLE",
    }
    ```

## Крок 2. Примусовий запуск прошивки

Для старту оновлення необхідно надіслати команду на «натискання» внутрішньої сервісної кнопки. Спробуйте виконати це найпростішим способом через браузер, а якщо він видасть помилку методу — скористайтеся терміналом.

=== "Спосіб 1: Через Браузер (Найпростіший)"

    Скопіюйте це посилання, вставте його в адресний рядок вашого браузера, замініть `<IP_ПРИСТРОЮ>` на реальну локальну IP-адресу вашого пристрою та натисніть **Enter**:
    ``` http
    http://<IP_ПРИСТРОЮ>/button/Firmware Update/press
    ```

    !!! tip
        Якщо сторінка завантажилася без критичних помилок або залишилася просто пустою — запит успішно прийнято пристроєм.

=== "Спосіб 2: Через Термінал (cURL)"

    Якщо браузер видав помилку про непідтримуваний метод (`Method Not Allowed`), надішліть точний `POST`-запит через термінал або командний рядок Windows:
    ``` bash
    curl -X POST "http://<IP_ПРИСТРОЮ>/button/Firmware Update/press"
    ```

!!! danger "Важливе застереження під час оновлення"
    Після надсилання запиту **не вимикайте SvitloBot з розетки** та не перезавантажуйте його примусово!

    Зачекайте **1–2 хвилини**. Контролер самостійно виконає наступні кроки:

    1. Звернеться до репозиторію **Svitlo**Bot.
    2. Автоматично завантажить актуальний файл під вашу архітектуру чіпа (ESP32 чи ESP8266).
    3. Виконає OTA-оновлення та перезапуститься вже з повністю відновленим, актуальним та робочим WEB-інтерфейсом.

!!! warning annotate "Якщо налаштовано авторизацію"
    Якщо раніше на пристрої було задано логін та пароль для входу в інтерфейс, звичайний запит поверне помилку `401 Unauthorized`. При використанні cURL обов'язково додайте прапорець аутентифікації:
    ``` bash
    curl -u admin:ваш_пароль -X POST "http://<IP_ПРИСТРОЮ>/button/Firmware Update/press"
    ```

*[ESP32]: Серія мікроконтролерів типу «система на кристалі» китайського виробника Espressif, що мають інтегровані контролери Wi-Fi і Bluetooth, низьке енергоспоживання і невисоку ціну.
*[ESP8266]: Мікроконтролер китайського виробника Espressif з інтерфейсом Wi-Fi. Наприклад, NodeMCU або Wemos D1 Mini.
*[OTA]: (Over-the-Air) Технология беспроводной загрузки и установки обновлений программного обеспечения или прошивки (firmware) на устройство по Wi-Fi или сотовой сети, без необходимости физического подключения к компьютеру через кабель (USB).
